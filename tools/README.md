# 빌드 도구

한글판 ISO 를 만드는 전체 파이프라인. 순서대로 실행한다.
작업 폴더에 원본 ISO 경로가 잡혀 있어야 한다 (`isolib.py` 의 `ISO_PATH`).

```bash
python bootstrap.py       # ISO -> common.bin, 원본 폰트 추출
python mapping.py         # 번역에 쓰인 한글 -> 한자 코드 배정
python build_font_kr.py   # 한글 글리프를 한자 슬롯에 얹은 폰트 생성
python insert.py          # 번역문을 PRCS 스크립트에 재삽입
python build_iso.py       # 아카이브 재조립 + ISO 기록
python verify_strict.py   # 원본 ISO 와 위치별 전수 대조
```

`extract_text.py` 는 원문을 JSON 으로 다시 뽑을 때만 쓴다(이미 `../text/` 에 있음).

## 모듈

| 파일 | 역할 |
|---|---|
| `isolib.py` | ISO9660 읽기 |
| `sectpack.py` | SECTPACK 아카이브 읽기 |
| `lz.py` | 게임 LZ77 압축/해제 |
| `ptr.py` | SIR0 재배치 포인터 리스트 |
| `fonts.py` | 폰트 컨테이너·글리프 파싱, 렌더 |
| `prcs.py` | PRCS 스크립트 문자열 탐색 |
| `textutil.py` | Shift-JIS 문자열 유틸 |
| `build_font.py` | 글리프 렌더링(`render()`) |

## 핵심 수치

| 항목 | 값 |
|---|---|
| 번역 문자열 | 20,524 |
| 배정 한글 | 1,202종 → 공통 한자 코드 1,847개 중 앞에서부터 |

## 주의점

- **`NovelFontList.dat` 은 원본이 무압축**이다. 압축해서 넣을 때 SECTPACK TOC 의
  압축 플래그(`id |= 0x8000`)를 반드시 같이 켜야 한다. `build_iso.py` 의
  `comp_override` 가 이 일을 한다. 놓치면 게임이 압축 헤더를 SIR0 로 읽어 폰트가 깨진다.
- **`BH.bin` 은 LBA 를 1 섹터 뒤로 옮긴다.** `SI_A.bin` 뒤에 여유 섹터가 0 이라
  확장분을 넣을 자리가 없기 때문. ISO 디렉터리 레코드의 LBA/크기를
  little/big endian 양쪽 다 갱신해야 한다.
- PRCS 에는 파일 내 절대 오프셋 참조가 없다(측정: 경계 일치율 1.20% vs 무작위 0.91%).
  그래서 문자열 길이를 바꿔도 안전하다.
- 한글은 원본 한자 **코드를 그대로 쓴다**. 코드를 재배치하면 배정 안 된 한자가
  흰 박스로 나온다(초기 시도에서 확인됨).

## 분홍색 키워드 — `*_keyword.bin` / `tools/keywordfix.py`

본문 중 추리에 쓰는 조각(화면에서 **분홍색**)의 위치표다. 번역으로 문장 길이가
바뀌면 이 표도 같이 고쳐야 한다. 안 고치면 엉뚱한 글자가 분홍색이 되고,
한국어가 원문보다 짧은 블록에서는 **범위를 벗어나 실기에서 멈춘다.**

```
u32 count      # 스크립트 블록 수 (라벨 0x0f 구간 수 - 1)
u32 0
레코드 × count # 블록 순서 그대로 1:1. 첫 블록(*_01_0000, 제목)은 제외
  type 0 : u32 0                                    # 분홍 글자 없음
  type 1 : u32 1, u8 cnt, u16 pad, u8 seg,
           cnt × { u8 start, u8 end, u32 pad }      # end 포함
```

`start`/`end` 는 그 블록 본문의 **글자 인덱스**이고, 원문에서 재보면 언제나
조각(op 0x01 문자열) 경계에 정확히 맞는다 — 430개 레코드 / 682개 범위 전부 확인.

### δ — 게임이 세는 인덱스는 조금 더 크다

한자 읽기(루비)가 붙은 자리마다 게임 버퍼에 한 글자가 더 들어간다. 그 차이를
δ 라 하면 `start = (조각 앞까지의 길이) - δ` 이고, δ 는 **레코드가 아니라
범위마다** 다르다(앞쪽 루비가 쌓이므로 블록 안에서 0 부터 단조 감소).
이걸 레코드 하나에 δ 하나로 잘못 보면 50개가 어긋난다.

### 고치는 법 — δ 를 몰라도 된다

δ 를 만드는 요소(오프코드·루비·`㊤` 마커)는 번역이 건드리지 않으므로 한국어에서도
그대로다. 그래서 **조각 경계에서의 한·일 길이 차이만큼 밀어 주면** δ 가 저절로
보존된다.

```
새 start = start + (한국어 p0 앞까지 길이 - 일본어 p0 앞까지 길이)
새 end   = end   + (한국어 p1 까지  길이 - 일본어 p1 까지  길이)
새 seg   = seg   + (한국어 블록 길이 - 일본어 블록 길이)
```

`python tools/keywordfix.py` → `keyword_payloads.pkl` → `build_iso.py` 가 반영한다.
`start`/`end` 가 u8 이므로 결과가 0~255 를 벗어나면 그 레코드는 건너뛴다.
