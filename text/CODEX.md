# 작업 지시서 — Trick × Logic Season 1 한글화 번역

PSP 추리 어드벤처 게임 『トリック×ロジック』(Trick × Logic) Season 1 의
일본어 원문 **20,524개**를 한국어로 번역한다. 원문은 이미 게임 ISO 에서
추출되어 이 폴더의 JSON 에 들어 있다.

너는 **번역만** 하면 된다. 추출·재삽입·폰트 작업은 이미 되어 있거나 별도로 진행된다.

---

## 1. 파일 구성

| 파일 | 설명 |
|---|---|
| `TU/TU_A/NF/NF_A/FW/FW_A/KM/KM_A/SI/SI_A/BH/BJ .json` | 시나리오별 원문 (`_A` 는 추리 파트) |
| `common.json` | 메뉴·튜토리얼·시스템 UI |
| `_index.json` | 메타데이터·표시 한계·파일 목록 |
| `charset.json` | **쓸 수 있는 문자 목록** |
| `_baseline.json` | 원문 무결성 검사용 해시 (건드리지 말 것) |
| `README.md` | 데이터 구조 상세 |

도구 (모두 `python <이름>` 으로 실행):

| 도구 | 용도 |
|---|---|
| `next_chunk.py <파일> [그룹수]` | 아직 번역 안 된 묶음을 꺼낸다 |
| `apply.py <번역.jsonl>` | 번역 결과를 JSON 에 반영한다 |
| `validate.py [파일]` | 규칙 위반을 검사한다 |

## 2. 절대 규칙

위반하면 게임이 깨지거나 글자가 안 나온다. `validate.py` 가 전부 잡아낸다.

1. **`ko` 필드만 채운다.** `id`·`ja`·`loc`·`max_chars`·`group` 등 다른 필드는
   한 글자도 바꾸지 않는다. `loc` 은 재삽입 좌표라 틀어지면 복구 불가다.
2. **`max_chars` 를 넘기지 않는다.** 대사창은 22자 × 2줄 = **44자**가 한계다.
   넘으면 화면에서 잘린다. 한글은 전각이라 일본어와 폭이 같으니 글자 수를 그대로 세면 된다.
3. **개행·탭·제어문자 금지.** 게임이 자동으로 줄을 바꾼다. `\n` 을 넣으면 안 된다.
4. **한자 금지.** 한자 글리프 자리를 한글로 덮어쓸 예정이라 한자는 표시되지 않는다.
5. **한글은 완성형 2350자만.** `charset.json` 의 `hangul.chars` 에 있는 음절만 쓸 수 있다.
   (「똠」「뷁」같은 완성형 밖 음절은 표시 불가)
6. **한글 종류 상한 1,914자.** 번역 전체에서 쓰인 서로 다른 음절이 폰트 슬롯 수를
   넘으면 안 된다. 현학적이거나 희귀한 어휘를 피하고 평이한 표현을 쓰면 자연히 지켜진다.
   `validate.py` 가 현재 사용 종류를 알려준다.
7. 그 밖에 쓸 수 있는 문자는 `charset.json` 의 `ascii`·`kana`·`punctuation_fullwidth` 뿐이다.
   전각 기호(「」『』…―★○ 등)와 영숫자는 쓸 수 있다.

### ⚠ 8. 제어 태그를 절대 건드리지 마라 (게임이 죽는다)

이 게임은 눈에 보이는 문자를 **인라인 제어 명령**으로 쓴다. 지우면 스크립트 파서가
깨져서 **게임이 강제 종료된다.** (실제로 한 번 이 문제로 크래시했다.)

| 원문 형태 | 정체 | 처리 |
|---|---|---|
| `㊤ ㊥ ㊦ ㊧ ㊨` | 인라인 제어 태그 (루비·페이지 등) | **원문과 같은 개수·같은 순서로 유지** |
| `㊤` 한 글자만 있는 문자열 | 제어 명령 | **번역하지 말고 `ko` 에 원문 그대로** |
| `ｪ` 등 반각 가타카나 한 글자 | 제어 명령 | **번역하지 말고 원문 그대로** |
| 전각공백(`　`)만으로 된 문자열 | 레이아웃용 | **번역하지 말고 원문 그대로** |

`A㊦㊨B` 처럼 문장 중간에 태그가 있으면, **태그는 그 자리에 그대로 두고
앞뒤 텍스트만** 한국어로 옮긴다:

```
원문:  ファントム㊦㊨飛鳥を見やる。
번역:  팬텀㊦㊨아스카를 바라본다.        ← 태그 위치·개수 유지
잘못:  팬텀 아스카를 바라본다.           ← 태그 삭제 = 게임 죽음
```

`validate.py` 가 태그 개수·순서를 대조해 어긋나면 오류로 잡는다.

### ⚠ 9. 반각 문자를 쓰지 마라

이 게임의 원문은 **반각 영숫자·기호를 단 한 번도 쓰지 않는다**(20,524건 전수 확인).
반각을 넣으면 게임이 오동작한다 — 반각 공백은 줄바꿈 처리에서 **크래시**,
반각 영숫자는 버튼 아이콘 치환이 깨져 **흰 사각형**으로 나온다(둘 다 실기 확인).

삽입 단계에서 자동으로 전각 변환되니 `ko` 에는 편한 대로 써도 되지만,
아래처럼 **원문이 쓰는 문자**를 그대로 쓰는 편이 안전하다.

| 쓰지 말 것 | 대신 | 원문 사용 |
|---|---|---|
| `,` | `、` | 12,178회 |
| `.` | `。` | 4,854회 |
| `'…'` | `『…』` | 379회 |
| 반각 공백 | 전각공백 `　` | 3,679회 |

### ⚠ 11. 조각 경계의 띄어쓰기를 빠뜨리지 마라

조각을 따로 번역하면 **경계에서 띄어쓰기가 사라진다.** 일본어는 원래 띄어쓰기가
없어 눈에 띄지 않지만, 한국어는 낱말이 들러붙어 읽기 어려워진다.
(실제로 6,089곳에서 이 문제가 생겨 일괄 수정했다.)

```
조각1: 일류 호텔의        조각2: 피로연장으로 착각할 만큼
화면:  일류 호텔의피로연장으로 착각할 만큼      ← 붙어 버린다
고침:  조각1 끝에 공백을 넣어 '일류 호텔의 '
```

뒤 조각이 **조사·어미**(을/를/이/가/에게/라는/하고…)로 시작하면 붙이고,
새 낱말로 시작하면 **앞 조각 끝에 공백을 넣는다.** 애매하면 띄운다.

`tools/spacefix.py` 의 `need_space(앞, 뒤)` 가 이 판정을 한다.

### ⚠ 12. 새 글자를 쓰면 폰트를 다시 만들어야 한다

폰트 슬롯은 **번역에 실제로 쓰인 한글만** 배정한다(현재 1,207자 / 가용 1,847).
번역을 고쳐 새 음절이 등장하면 `mapping.py` -> `build_font_kr.py` 를 다시 돌려야
하며, 건너뛰면 삽입 단계에서 인코딩 오류가 난다.

### ⚠ 10. 대사가 아닌 문자열은 번역하지 마라

`_noteditable_ids.json` 에 적힌 **65건**은 대사 출력 명령이 아니라
UI 라벨 등 **고정 길이 슬롯**이다. 길이가 바뀌면 게임이 죽는다.
(탐정 모드 탭 1자 라벨을 2자로 번역했다가 크래시한 사례가 있다.)

이 id 들은 `ko` 에 원문을 그대로 두어야 하며, `validate.py` 가 검사한다.

## 3. 반드시 알아야 할 것 — 대사는 조각으로 쪼개져 있다

이 게임은 한 문장을 **여러 조각으로 나눠** 저장한다 (루비·강조·키워드 표시 때문).
`prologue` 는 76%가 6자 이하이고, 문장부호로 끝나는 조각은 절반도 안 된다.

**조각을 하나씩 따로 번역하면 문장이 완전히 망가진다.**

그래서 조각들을 **문장 그룹**으로 묶어 두었다 (20,524 조각 → 11,468 그룹).
`next_chunk.py` 는 항상 그룹 단위로 꺼내 주며, 각 그룹에는:

- `full_ja` — 그룹 전체를 이어붙인 원문 ← **이걸 보고 번역한다**
- `parts[]` — 실제로 채워야 할 조각들 (각각 `id`, `ja`, `max`)

**작업 방식:** `full_ja` 를 하나의 문장으로 읽고 자연스러운 한국어로 옮긴 뒤,
그 번역을 `parts` 에 나눠 담는다.

조각 경계를 원문과 똑같이 맞출 필요는 **없다.** 문자열마다 길이 필드가 따로 있어
길이를 자유롭게 바꿀 수 있다. 나누기 어색하면 **한 조각에 몰아넣고 나머지는 빈 문자열**로
두어도 된다. 다만 각 조각의 `max` 는 지켜야 한다.

## 4. 작업 루프

한 번에 다 하려 들지 말고 아래를 반복한다. 한 번에 **30~50 그룹**이 적당하다.

```bash
# 1) 번역할 묶음을 꺼낸다
python next_chunk.py TU_A.json 40 > chunk.jsonl

# 2) chunk.jsonl 을 읽고 번역해서 trans.jsonl 을 만든다 (형식은 아래)

# 3) 반영한다
python apply.py trans.jsonl

# 4) 검사한다 — 오류가 있으면 고치고 다시 3)
python validate.py TU_A.json
```

`trans.jsonl` 형식 — 한 줄에 그룹 하나:

```json
{"group":"TU_answer/g0007","parts":[{"id":"TU_A/TU_answer/0031","ko":"번역문"},{"id":"TU_A/TU_answer/0032","ko":""}]}
```

`{"id":"...","ko":"..."}` 처럼 조각 단위로 한 줄씩 써도 된다.

**진행 순서** — 작은 파일부터 감을 잡고 큰 파일로 간다:

```
TU_A(263) → TU(474) → common(810) → BJ(1054) → NF_A(1369) → FW_A(1409)
→ NF(1728) → FW(1578) → KM_A(1989) → SI_A(2244) → KM(2415) → SI(2401) → BH(2790)
```

작업 도중 중단되어도 `next_chunk.py` 가 안 된 것만 꺼내 주므로 그냥 이어서 하면 된다.

## 5. 번역 지침

**톤** — 2010년작 일본 추리 어드벤처다. 등장인물 대사는 자연스러운 구어체로,
지문·소설 파트(`category` 가 `scenario`·`tips`·`question`)는 문어체로 옮긴다.
직역투("~것이다", "~해 버렸다")를 피하고 한국어로 읽히게 쓴다.

**일관성이 가장 중요하다.** 추리 게임이라 같은 단어가 단서로 반복 등장한다.
인명·지명·사건명·트릭 용어는 반드시 같은 표기를 유지한다.
`glossary.json` 파일을 만들어 `{"원문":"번역"}` 형태로 관리하고, 새 고유명사가
나올 때마다 추가한 뒤 이후 작업에서 참조한다.

**등장인물** — `speaker_hint` 에 로마자로 들어 있다 (실제 화자와 다를 수 있으니 참고용).
등장 빈도: `yosikawa`(5,776) `marunouchi`(2,694) `tukasa`(2,496) `yama`(673) `kaoru`(434).
한국어 표기는 처음 나올 때 정해 `glossary.json` 에 기록하고 끝까지 고수한다.

**분량** — 44자 제한 때문에 일본어보다 길어지기 쉽다. 조사·군더더기를 덜어내
압축하되 의미를 빠뜨리지 않는다. 도저히 안 들어가면 문장을 둘로 나눠
그룹 내 다른 조각에 넘긴다.

**카테고리별 성격**

| category | 내용 |
|---|---|
| `scenario` | 시나리오 본편 (지문 + 대사 혼재) |
| `answer_begin` / `giveup` | 추리 파트 정답·포기 시 대사 |
| `question` / `inspiration` | 문제 제시·착상. 추리의 핵심이라 **정확도 최우선** |
| `hint` / `tips` | 힌트·용어 설명 |
| `prologue` / `bridge` / `interval` | 도입부·장면 전환 |
| `profile` / `outline` / `report` | 인물 정보·사건 개요 |
| `common_*` | 메뉴·버튼·시스템 메시지. **UI 라 특히 짧게** |

**추리 게임 특성상 주의** — 단서가 되는 표현(사망 시각, 위치 관계, 증언의 모순,
말장난 등)은 원문의 뉘앙스를 임의로 매끄럽게 다듬지 말 것. 트릭이 성립하지 않게 된다.
애매하면 원문에 가깝게 두고 `notes.md` 에 기록해 둔다.
